# ossie-tableau

Two-way converter between Tableau classic data sources and [Apache Ossie](https://ossie.apache.org/).

- **Tableau to Ossie:** `.tds`, `.twb`, `.tdsx` and `.twbx` files to Ossie YAML (`ossie-tableau convert`).
- **Ossie to Tableau:** Ossie YAML to a logical-layer `.tds` (`ossie-tableau to-tds`; Snowflake and BigQuery are tested).

Every element that cannot be represented is reported as a classified loss and never dropped silently (see [Known limitations and lossiness](#known-limitations-and-lossiness) and [LIMITATIONS.md](LIMITATIONS.md)).

## Layout

| Path                   | Purpose                                                                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/ossie_tableau/` | `convert.py` (Tableau to Ossie), `formula.py` (formula tokenizer), `tds_writer.py` (Ossie to TDS), `losses.py` (loss catalogue), `stash.py` (versioned stash codec), `warehouse.py`, `cli.py` |
| `tests/`             | Inline unit tests (`pytest -m unit`)                                                                                                                                                                      |
| `docs/`              | `loss-catalog.md` and `expression-mapping.md`, generated by `tools/gen_docs.py`                                                                                                                       |

## Usage

Needs [`uv`](https://docs.astral.sh/uv/).

```sh
cd tableau
uv sync

# Tableau -> Ossie
uv run ossie-tableau convert <file-or-dir> -o out/

# Ossie -> Tableau logical-layer TDS
uv run ossie-tableau to-tds model.ossie.yaml [--warehouse-type snowflake] \
  --server <account>.snowflakecomputing.com --warehouse WH --database DB --schema SCH [--role ROLE] -o out/
```

Add `--strict` (exit 1 on any `error`-severity loss) or `--strict-kinds k1,k2` (exit 1 on the listed kinds) to either command. The full list of kinds, categories, severities and remedies is in [docs/loss-catalog.md](docs/loss-catalog.md).

`convert` writes `<file>__<datasource>.ossie.yaml` plus a `.loss.json` per datasource (each loss has `kind`, `name`, `detail`, `category`, `severity`, `remedy`). `to-tds` writes `<model>.tds` plus `<model>.tds.loss.json`. The TDS contains no credentials; supply them when publishing.

## What converts

### Tableau to Ossie

- Datasets, from `object-graph` objects (modern) or top-level relations (legacy, including the inner `.twb` of `.twbx`). A warehouse table name that differs from the Ossie dataset name is recorded as an `ai_context` synonym.
- Fields: type, dimension or measure, time flag, caption (as label) and description. Captions and warehouse remote-column names that differ from the Ossie name are recorded as `ai_context.synonyms`. Structured `ai_context` (`instructions`, `synonyms`, `examples`) on the document, dataset, field or metric round-trips through `<user:ossie-ai-context>`. Member/value aliases (EMEA → Europe) stay in the TABLEAU extension.
- Relationships, from `object-graph` equality expressions (multi-column AND supported) and legacy `join` trees. Cardinality comes from `unique-key` hints. The first distinct key marked for a dataset becomes `primary_key`; later keys stay on `unique_keys`.
- Union relations, as a single `UNION [ALL]` dataset.
- Aggregate calculations over physical columns, as metrics (TABLEAU dialect plus warehouse SQL when the catalog can translate; `[dataset].[field]` references). A reference to another metric is a bare identifier when the name is legal (`metric_inlined` only when it is not). Mixed or cross-dataset aggregates are kept (`sql_untranslated` when warehouse SQL cannot be produced). Number of Records becomes `COUNT(*)`. Single-table row-level calculations become TABLEAU-dialect fields.
- Field metadata (hidden, semantic role, default aggregation and format, folder), legacy join type and named connection, kept as `TABLEAU` `custom_extensions`.
- Unconverted calculations, preserved verbatim in a document-level `TABLEAU` extension. Unknown `<datasource>` children are stashed as `unmodeled_xml` and replayed by `to-tds`. Non-`TABLEAU` `custom_extensions` round-trip through `<user:ossie-foreign-extensions>`.

### Ossie to Tableau

- One federated connection (class and attributes from the warehouse descriptor), one relation per dataset (`text` relation for subquery sources), the object graph with relationships, one column per field and one measure calculation per metric.
- Structured `ai_context` is written as `<user:ossie-ai-context>` on the datasource, object or column. Non-`TABLEAU` extensions are written as `<user:ossie-foreign-extensions>`. Unknown datasource children are replayed from the `unmodeled_xml` stash.
- Expression translation order: TABLEAU dialect expression (field references rewritten to local column names, then bare metric names to the metric's calculation local), then a reverse rewrite of the SQL expression through the function catalogue (see [docs/expression-mapping.md](docs/expression-mapping.md)), otherwise a classified loss.
- Output is deterministic.
- Table paths keep the full `[DATABASE].[SCHEMA].[TABLE]` form. The collection relation lists tables in relationship depth-first order from the root, because Tableau pairs logical tables with collection relations by position.
- Datasource root attributes (`formatted-name`, `source-platform`, and `caption` only if the original had one) are stashed in the `TABLEAU` extension and restored. A `federated_*` model name is never written as a caption, so Tableau shows the published name. A hand-authored model gets its name as the caption.

## Input handling and safety

- `.twbx`/`.tdsx` archives are read in memory (no extraction); **every** inner `.twb`/`.tds` is converted, and output names are prefixed with the inner file name when there is more than one.
- XML with `DOCTYPE`/`ENTITY` declarations, or members larger than 256 MiB, are rejected (`FAIL`, exit code 1).
- Each data source becomes its own document. `manifest.json` in the output directory lists every output, skipped data source and failure.
- `--warehouse-type {snowflake,bigquery}` overrides connection-class detection. Unregistered classes (postgres, redshift...) raise an `unknown_warehouse` loss.
- `--no-clobber` refuses to overwrite existing outputs; `-q` prints only problems.
- Data blending across worksheets is not modeled and raises a `blend` loss. Each loss's `kind` is its stable code and `name` the object it refers to.

## Coverage matrix

| Tableau construct                                | Result                                               | Loss kind                                                             |
| ------------------------------------------------ | ---------------------------------------------------- | --------------------------------------------------------------------- |
| Tables, joins, unions, custom SQL, relationships | Ossie datasets and relationships                     | `source_qualified`, `no_tables`                                   |
| Calculations, LOD, table calcs, RAWSQL           | Field/metric expressions (Snowflake, BigQuery, ANSI) | `unresolved_reference`, `sql_unreconciled`, `rawsql_translated` |
| Parameters                                       | Kept or inlined (`--inline-parameters`)            | `parameters`                                                        |
| Groups, sets, hierarchies, aliases               | Kept in the TABLEAU extension                        | `group`, `set`, `hierarchy`, `aliases`                        |
| Extracts                                         | Live connection converted                            | `extract`                                                           |
| Data blending across worksheets                  | Not modeled                                          | `blend`                                                             |
| Repeated connection and tables                   | Each converted, cross-referenced                     | `duplicate_datasource`                                              |
| Unregistered warehouse class                     | Generic ANSI SQL                                     | `unknown_warehouse`                                                 |
| BigQuery wildcard tables, `@param` custom SQL  | Kept verbatim                                        | `wildcard_table`, `query_parameter`                               |
| Files (Excel, CSV), published sources            | Skipped                                              | `file_source`, `published_datasource`                             |

Every loss has a stable `kind` (its issue code) and a `name` (the object it refers to). The full table with categories, severities and remedies is `docs/loss-catalog.md`.

## Supported warehouses

`src/ossie_tableau/warehouse.py` describes each warehouse (sqlglot dialect, Ossie dialect names, Tableau connection class and attributes). Entries: `snowflake` and `bigquery`. Reading a saved connection and writing `to-tds` use the descriptor, selected by `--warehouse-type` (BigQuery also takes `--project`, plus `--database`/`--schema` for the dataset). A datasource's warehouse is inferred from its connection class, and its calculations are tagged with that warehouse's Ossie dialect. The calculation catalogue (`calc_catalog.py`) holds Snowflake templates; other warehouses use per-dialect `Override` templates or the `PORTABLE` allowlist, and anything else is reported as not translated rather than guessed. BigQuery results are in [docs/expression-mapping.md](docs/expression-mapping.md) and were checked against live BigQuery. To add a warehouse, add a `Warehouse` entry, overrides, and tests in `tests/test_warehouse.py` and `tests/test_calc_bigquery.py`.

## Known limitations and lossiness

### Policy

Nothing is dropped silently. Each unrepresentable element becomes a `Loss(kind, name, detail)` in the `.loss.json` (or in the result object), and tests assert that every kind is known and that round-trip differences are fully explained by recorded losses.

### Tableau to Ossie: not representable

| Loss kind                                                                                                                                                                                                                                                                                      | Meaning                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `row_level_calc`, `lod`, `table_calc`, `rawsql` (whole-formula `{AGG}`, `{FIXED : AGG}` and `TOTAL(AGG)` metrics are now emitted with a window SQL form, `lod_translated`; `INCLUDE`/`EXCLUDE`, dimensioned `FIXED`, `RUNNING_*`, `RANK` and `LOOKUP` stay losses) | Calculations Ossie metrics cannot express (row-level ones become fields only for single-table, resolvable cases; `RAWSQL_*` over resolvable columns becomes a SNOWFLAKE field, `rawsql_translated`)                                                           |
| `group`, `bin`, `categorical_bin`, `passthrough`, `calc_class`, `hierarchy`, `folder`, `aliases`                                                                                                                                                                               | Tableau-only constructs (member/value aliases stay in the TABLEAU extension; they are not field synonyms)                                                                                                                                                         |
| `parameters`, parameter references                                                                                                                                                                                                                                                           | Parameters are not modelled; `convert --inline-parameters` substitutes current values (`parameter_inlined`, approximated)                                                                                                                                     |
| `record_count`                                                                                                                                                                                                                                                                               | Tableau Number of Records (`1`) is emitted as `COUNT(*)` (info)                                                                                                                                                                                               |
| `sql_untranslated`                                                                                                                                                                                                                                                                           | A mixed or cross-dataset metric kept its TABLEAU expression; warehouse SQL could not be produced                                                                                                                                                                  |
| `unmodeled_xml`                                                                                                                                                                                                                                                                              | Unknown `<datasource>` children stashed and replayed by `to-tds`. Non-`TABLEAU` extensions use `<user:ossie-foreign-extensions>`                                                                                                                          |
| `non_numeric_result`, `non_numeric_aggregate`                                                                                                                                                                                                                                              | Metric guards: non-numeric results and aggregates are parked                                                                                                                                                                                                      |
| `metric_inlined`                                                                                                                                                                                                                                                                             | A referenced metric whose name cannot stand as a bare identifier is inlined                                                                                                                                                                                       |
| `relationship`, `relationship_cardinality`                                                                                                                                                                                                                                                 | Operands that are not `[table].[col]` (for example dummy cross joins); cardinality is assumed (first endpoint is the many side) unless a `unique-key` hint exists. The first distinct key on a dataset is `primary_key`; later keys stay on `unique_keys` |
| `union`                                                                                                                                                                                                                                                                                      | Now a NULL-padded `UNION ALL` (approximated); only members with unknown columns fall back to the first member                                                                                                                                                   |
| `datasource_filter`, `initial_sql`, `row_level_security`, `extract`, `published_datasource`                                                                                                                                                                                          | Not modelled                                                                                                                                                                                                                                                      |
| `no_tables`, `no_column_metadata`, `unsupported_object`, `unsupported_datatype`                                                                                                                                                                                                        | Connection-only datasources, columns that cannot be attributed, and spatial/tuple/table types (mapped to String)                                                                                                                                                  |

Other Tableau-to-Ossie limits:

- **Naming:** the Tableau local name and caption are stashed (witness-guarded) and restored by `to-tds`; if the Ossie name or label was edited since, the stash is stale and ignored (`stash_stale`). Captions and remote-column names that differ from the Ossie name are also `ai_context.synonyms`.
- **Connection database:** `dbname` is read and two-part sources are qualified (`source_qualified`); the connection is stashed for `to-tds` defaults.
- **Worksheets and dashboards:** out of scope.

### Ossie to Tableau: not representable

- `untranslatable_expression`: an expression with no TABLEAU dialect that is not a simple aggregate or a bare column. No guessing and no RAWSQL.
- `relationship_key_synthesized`: a join column that is not a declared field is added as a hidden column.
- `datatype_defaulted`: a field with no datatype gets one from its dimension flags.
- Time/datetime-with-timezone, time and opaque types map to the closest Tableau type.
- No credentials are written. Only Snowflake and BigQuery connections are written; data sources have a logical layer, not extracts.
